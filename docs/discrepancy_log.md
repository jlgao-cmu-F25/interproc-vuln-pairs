## Entries

### D1. Paper says 509 CVEs; Tables 4–7 use 451

- **Paper:** abstract and Sec. 8 say "509 vulnerabilities". Tables 5–7 have at most N = 451.
- **Data:** `data/prompts/` has 509 CVE folders: C 356, C++ 18, Python 77, **Java 58**. Every model output file has exactly the 451 C/C++/Python CVEs. The Java prompts were built but never sent to a model.
- **Effect:** none on the tables. "509" counts the dataset, and the tables cover 451 of those CVEs. We report 451.

### D2. Unparsed answers are dropped from N, not counted as misses

- **Paper (Sec. 3.2):** non-conforming outputs are "excluded from the quantitative analysis". This matches the shipped files: the label is `None` and the CVE is not counted in N.
- **What the `None`s are** (`unparsed_counts.csv`). Most come from missing context: 214 CVEs have no callees and 230 have no callers. The rest are real answers that failed to parse:

  | Model | CO | CC | CK |
  |---|---|---|---|
  | Gemini 3 Flash | 43 (23 empty, 20 cut off mid-sentence) | 67 | 72 |
  | GPT-5 Mini | 9 (all empty) | 7 | 4 |
  | Claude Haiku 4.5, GPT-4.1 Mini | 0 | 0 | 0 |

  Gemini's text answers stop mid-reasoning ("Wait, I should be more precise…"). GPT-5 Mini's answers are empty strings. Both patterns fit reasoning tokens using up the 4096-token output limit that every `run_*.py` sets.
- **Effect** (`sensitivity_none_as_wrong.csv`). If a failed answer counts as a miss, which is the protocol in our proposal:
  - Gemini 3 Flash CO accuracy falls from 0.985 to **0.891** (F1 from 0.993 to 0.943).
  - Gemini CC falls from 0.953 to **0.684**, and CK from 0.960 to **0.647**.
  - GPT-5 Mini CO falls from 0.907 to 0.889.

  Gemini's "best model" result relies partly on dropping 10–33% of its answers. Under this rule it ranks below Claude Haiku in every context. The paper does not report the failure rate. The McNemar tests in Table 4 have the same blind spot, because they only use CVEs where both answers parsed.
- **Our protocol:** retry once, and count a second failure as a miss. This applies to the live re-run and to the paired study.

### D3. Temperature is not 0 for GPT-5 Mini

- **Paper (Sec. 3.2):** "setting the temperature to 0".
- **Code:** `run_openai.py` ships with `MODEL = "gpt-5-mini"` and `TEMPERATURE = 1.0`. The GPT-5 API only accepts 1. `run_anthropic.py` and `run_gemini.py` use 0.0.
- **Effect:** GPT-5 Mini results are one sample from a stochastic model. This is already in our proposal: one sample per prompt, noted as a threat.

### D4. The shipped scripts don't run as-is

- `src/utilities/mcnemar_analysis.py` and `mcnemar_language_analysis.py` read `<script dir>/dashboard/results/`. After the repo was reorganised, the files live in `data/outputs/` (also mirrored in `dashboard/results/` at the repo root).
- `mcnemar_language_analysis.py` also needs `data/ReposVul.jsonl`, which is not shipped. `data/outputs/cve_languages.json` has the same information, and it agrees with the prompt folders for all 451 CVEs.
- The `run_*.py` scripts read `prompts_reasoning/`, which does not exist. The prompts are in `data/prompts/<lang>/<CVE>/`.
- There is no `requirements.txt`. The README lists only the tree-sitter packages. The analysis needs `numpy scipy pandas`, and the runners need `openai anthropic google-genai python-dotenv`.
- The scripts read one API key per language (`C_OPENAI`, `CPP_OPENAI`, `PYTHON_OPENAI`, …).
- **Fix:** `repro/run_authors_scripts.py` imports the authors' module and repoints the two path constants. No other code changes. `repro/live_rerun.py` reads `data/prompts/c/` directly and uses a single `OPENAI_API_KEY`.

### D5. Holm α for tied p-values (supplementary per-language table only)

- In `mcnemar_by_language.json`, many tests share the same p-value (p = 1.0 and p = 0.4795 come up often, because b + c is tiny). Holm ranks tied p-values arbitrarily. The authors break ties by file order (Gemini, GPT-4.1, GPT-5, Haiku), and we break them by the paper's model order. So their per-row α differs from ours. **No significance decision changes**, and all other statistics match in 36/36 rows (`mcnemar_by_language_check.csv`).
- Table 4 itself has no such ties, and every α matches.

### D6. C++ text says the smallest CK sample is N = 1

- **Paper (Sec. 4.2):** "sample sizes collapse to as few as N = 1 under CK".
- **Data** (`cpp_ours.csv`): the smallest C++ CK sample is Gemini 3 Flash with **N = 2** (1 of 2 correct). N = 1 does occur in the per-language McNemar table, for Gemini CC-vs-CK in C++, which is probably what the sentence refers to.
- The other C++ statements hold: N is 18 / 6 / 5 for the largest model, and CO accuracy is ≥ 0.889 for all models.
- **Effect:** wording only.

### D7. Model names and versions

- Gemini is listed as "Gemini 3 Flash" in the paper, "Gemini 3.0 Flash" in the shipped JSON, and `gemini-3-flash-preview` in the code. A preview model can be retired, which is the risk listed in our proposal.
- Claude is pinned as `claude-haiku-4-5-20251001`. GPT-4.1 Mini and GPT-5 Mini use unpinned aliases. Our live re-run records the model string the API actually served (`served_models` in `live_rerun_summary.json`).
